# Conversion issues

The remaining issues of the conversion, i.e., what the current version does not convert or converts with a loss. The failure reasons of the [SBML test suite](testsuite.md#failure-reasons) measure them against the semantic test cases; what is converted is listed in [What is converted](index.md#what-is-converted) and [CellML to SBML](conversion.md#mapping).

## SBML to CellML

- **Units of an incomplete annotation.** The units of the variables are converted when every variable has units in the SBML model, see [Units](conversion.md#units); with a single compartment, species or parameter without units every variable stays `dimensionless`. A number without units in a formula is always `dimensionless`, CellML requires units on every number and SBML has none to give.
- **Unit warnings of libcellml.** libcellml 0.7.2 reduces a unit with a multiplier and an exponent as the CellML specification does ([cellml/libcellml#1463](https://github.com/cellml/libcellml/issues/1463) is fixed), but the unit check of its analyser still reports equations whose two sides reduce to the same base units as not equivalent, e.g., `mM x min^-1` and `litre^-1 x mmole_per_min`, both `10^-1.77815 x metre^-3 x mole x second^-1`, of a model in minutes and millimolar ([cellml/libcellml#1229](https://github.com/cellml/libcellml/issues/1229)). The warnings do not make a model invalid.
- **Initial assignments** are evaluated to initial values (libsbml's `expandInitialAssignments`), so the CellML model has the value but not the formula. An assignment which libsbml cannot evaluate (a call of a recursive function definition, a rateOf with a local parameter, a delay, or the value of such an assignment) stays unconverted with a warning. libsbml takes only 1 as true when it evaluates a number as a condition (`piecewise(0, 5, 1)` gives 1, test case 01282), where the rust converter, which evaluates the formula itself, takes a value which is not zero as true, as a simulator does.
- **An infinite or NaN initial value of a state** cannot be expressed: CellML initial values are real numbers (a constant gets the equation `x = INF` instead).
- **Metadata without a CellML element**: the names, notes and annotations of rules, function definitions, initial assignments, constraints and events are not converted, neither are annotations which are not RDF (e.g., of COPASI or layout tools). Everything else goes into the RDF file next to the CellML model, see [Metadata](conversion.md#metadata).
- **Events** become resets: every event gets a variable `<event>_trigger` with the equation `piecewise(1, trigger, 0)` and every assignment of the event a reset of its variable which fires when that variable reaches 1. A reset applies its value when it fires, so what the semantics of an event add beyond that is kept in the metadata of the conversion and applied to the event again by `cellml2sbml`: the **delay** of the event, its **priority**, the `initialValue` and the `persistent` flag of its trigger and `useValuesFromTriggerTime` (see [Metadata](conversion.md#metadata)). A CellML simulation of such a model fires the reset when the trigger holds, which is what a reset can express; the roundtrip SBML model has the complete event again. libopencor does not apply resets (see below), so the CellML simulation of a model with events differs from the SBML one.
- **Coupled algebraic rules**, which determine their variables only together (`x + y = 4`, `x - y = 2`), cannot be analysed by libcellml; an algebraic rule which determines no variable is skipped with a warning.
- **Operators CellML does not have.** A relation of more than two arguments, `a > b > c`, becomes the conjunction of its pairs, `quotient(a, b)` becomes `piecewise(ceiling(a / b), a / b < 0, floor(a / b))`, the integer division which truncates towards zero as the OpenMath dictionary the MathML of SBML follows defines it (libsbml evaluates the floored division instead, so the converted model and a simulation of the SBML model with libsbml differ for a negative operand), and `implies(a, b)` becomes `not a or b`. The **factorial** of a constant becomes the number it stands for, `factorial(4)` the number 24, since CellML has neither factorial nor gamma; one of a variable has no counterpart, and a model whose rules or kinetic laws use such a factorial is refused, naming the formula (an event which uses it is not converted, with a warning).
- **Time without differential equations.** CellML knows the variable of integration only from a differential equation: a model whose formulas use time without one gets the state `time_state` with `d time_state / d time = 1`, which makes time the variable of integration; a model which does not use time has no `time` variable and is simulated as a steady state.
- **An SBML id `time`** keeps its name, the variable of integration of the CellML model is `time_2` then. The comparison of the checks takes the time points of a result by their position and every variable by its name, so a model with such an id is compared; what the simulators return for the variable itself is another matter. sbmlsim-core gives one column for the selection `time`, the time points, so the value of a parameter of that id is missing from the SBML result, and the result of libopencor carries it under its full name (`sbml/time`) when the column of the time points is called `time` as well, which it is for a model without a variable of integration. The cases 01820 and 01821 of the test suite, three parameters named `time`, `Time` and `TIME`, therefore fail with `variable time missing in the result`, while BIOMD0000000437 of the BioModels check, a model with a species named `time`, passes every stage since the comparison keeps the two apart.
- **The delay symbol** is not converted, CellML has no delays: table 2.1 of the CellML 2.0 specification, the MathML of a model, has no `delay` and no history of a variable, and a delay differential equation is no system of ordinary differential equations, so there is no formula to write in its place. A rule or kinetic law which uses a `delay` therefore refuses the conversion, naming the formula (`CellML 2.0 has no 'delay': the formula '2 + delay(x, 0.2)' ...`), which both engines do: no document is written, with or without the validation. An event whose trigger or assignment uses one is not converted, with a warning, so the roundtrip SBML model has no such event either (the test suite reports the cases 01518, 01520, 01522, 01523, 01524, 01536 and 01592). The `delay` *of* an event is kept in the metadata, see Events above.
- **A variable a reset writes in an implicit equation.** libcellml takes a variable with an initial value in an implicit equation for its unknown, so the other variables of an algebraic rule lose their initial value to the equation `y = value` (see [Limitations](conversion.md#limitations)). A variable which an event writes loses it as well, and the roundtrip SBML model has that equation instead of the event assignment, which freezes the variable (the test suite reports the cases 01589 and 01592, and the model of 01577, whose two events write the variable of an implicit equation, does not integrate after the roundtrip). Without the equation libcellml reports the model as underconstrained.
- **rateOf** becomes the right-hand side of the equation of its variable. What the conversion cannot replace that way refuses the conversion of the model, as a `delay` does, since CellML has no `rateOf` outside a derivative: the rate of a variable which depends on itself, the rate of a variable an assignment rule sets and, in an initial assignment, a rate which reads a local parameter. The rate of a concentration in a compartment which changes needs the rate of the compartment, so it is converted when a rate rule changes the compartment and not when an assignment or algebraic rule does. An event assignment which uses a `rateOf` is converted, the rate it stands for is written in its place.
- **Unset initial values** of variables which no assignment rule or initial assignment sets are the value a simulator of the SBML model takes, with a warning: `0.0` for the initial amount of a species, `1.0` for the size of a compartment, a stoichiometry and the value of a parameter.

## CellML to SBML

- **External variables** are not supported and raise `CellML2SBMLConversionError`.
- **What the rust engine does not do.** Both conversions run in rust by default (see [Engines](conversion.md#engines)); for a CellML model the hierarchical conversion and a model the rust converter refuses (an operator SBML does not have, units the model does not define, rate equations which give each other's rate) are converted by the python engine, and the imports of a document are flattened with libcellml before the rust converter reads it. For an SBML model a hierarchical model is flattened with libsbml first; a formula which CellML cannot express (a `delay`, a `factorial` of a variable, a `rateOf` the conversion cannot replace) is refused by both engines. The metadata of the elements is converted by both engines in both directions, since a rust conversion gives the SBML element of every CellML element which stands for one.
- **The value a formula of an incomplete model has.** A parameter without a value is 1 for both converters, the value a simulator of the SBML model takes. The rust engine evaluates a formula which reads such a parameter with that value, where libsbml and with it the python engine evaluate it to NaN and the python engine falls back to the value of the quantity (the size 1 of a compartment, the value the model states as the guess of the solver for the variable of an algebraic rule). The two engines write a different initial value for such a model.
- **What libcellml does not analyse.** A system of coupled implicit equations (`x + y = 4`, `x - y = 2`) cannot be analysed by libcellml, and neither can 24 of the 101 models of the [Physiome](physiome.md) selection; the rust engine converts them, the python engine raises `CellML2SBMLConversionError`. A variable with an initial value which an equation determines is read by libcellml as the unknown of an implicit equation, which becomes an algebraic rule with its initial value as the guess; the rust engine writes the assignment rule the equation is and leaves the initial value out, since the rule holds at every time.
- **New base units** (units without a unit) have no SBML counterpart and are `dimensionless` in SBML, with a warning; only new base units named `item` become the SBML unit kind.
- **Resets** trigger on the equality of the test variable and the test value; a continuous simulator may not fire this trigger, see the [limitations](conversion.md#limitations).
- **Rate equations which give each other's rate.** A model whose rate equations give the rate of a state through the rate of another (`d x / d t = d y / d t + 1` and `d y / d t = 2 - d x / d t`) is read by the analyser of libcellml as an ODE model with those states and no equation at all, without reporting an issue, and its generator crashes on such a model ([cellml/libcellml#1531](https://github.com/cellml/libcellml/issues/1531)). The conversion would write an SBML model whose states stay at their initial value, so it refuses the model instead (`tests/data/coupled_rates.cellml`); `baroreflex` of the Physiome check is such a model, where libopencor dies in the same place. The rust converter refuses it as well, with the two states it names.
- **Resets in libopencor.** libopencor 1.20261113.0 does not apply the resets of a CellML model ([opencor/libopencor#596](https://github.com/opencor/libopencor/issues/596)): it integrates the model as if it had none, so the CellML side of a model with events or resets cannot be compared with the SBML side. The roundtrip SBML model has the events again and reproduces the original.
- **`not` in the C code of libcellml** ([cellml/libcellml#1532](https://github.com/cellml/libcellml/issues/1532)). The generator of libcellml 0.7.2 writes the operand of a `not` without parentheses, so `not(time > 5.5)` becomes `!voi > 5.5`, which C reads as `(!voi) > 5.5` and evaluates to 0 whatever the time is, and `not(a and b)` becomes `!(a) && (b)`, the negation of the first operand alone. The MathML is valid, the validator and the analyser of libcellml report nothing and only the generated code is wrong, so a simulation with libopencor, which compiles that code, returns a wrong trajectory without an error. A `not` of a variable (`!constants[0]`) is written correctly. The conversion writes the `not` the SBML model has, `implies(a, b)` among it (`not a or b`), and warns about every formula with such a `not`, since the document is valid and only the generated code is wrong; the cases 01279 and 01497 of the test suite, the `implies` in an assignment rule, therefore fail in the `libopencor` stage, where the SBML side and the roundtrip are right. The python profile of the generator writes `not voi > 5.5`, which python reads as the intended `not (voi > 5.5)`.
- **A unary `min` or `max` in libcellml** ([cellml/libcellml#1533](https://github.com/cellml/libcellml/issues/1533)). The generator of libcellml 0.7.2 crashes (segmentation fault) on a model whose mathematics holds a `min` or `max` of one argument, which MathML allows, and libopencor dies with it. The conversion therefore writes the argument itself (`max(a)` is `a`), as it does for every other n-ary operator of less than two arguments, so the cases 01280 and 01281 of the test suite, `max(time)` and `min(time)` in an assignment rule, are converted and simulated.
